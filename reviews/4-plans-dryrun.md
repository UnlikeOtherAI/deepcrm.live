## A. Execution-guide / cross-cutting failures

### A1. BLOCKER — 500-line rule vs verbatim-copy mandates
- **Where:** `00-execution-guide.md` Hard rules ("Every file ≤ 500 lines") + AGENTS.md, vs:
  - T03 (`01-scaffold.md`) "the exact contents of schema-engine §2 code block" → `schema.prisma` — the block is **609 lines** (measured). Fails the line cap at creation.
  - T22/T23/T24 register 11 / 9 / 3 tools in single files `api/src/mcp/tools/schema.ts`, `records.ts`, `links.ts`. The contracts for §2 alone are ~60 lines of zod plus 11 registrations with full descriptions and `.describe()`-copied args — realistically >500 lines for `schema.ts`, likewise `records.ts`.
  - T02 "copy verbatim" of contracts `errors.ts` conflicts with T02's own instruction (see B1) and would also force `ServiceError` into the contracts file that declares `ErrorCode = z.enum`.
- **Breaks:** the hard rule and the acceptance loop ("do exactly the steps; create only the files listed; never new modules unless listed") — the guide forbids the only escape (splitting into more modules).
- **Fix:** exempt verbatim copies and Prisma schema explicitly in the guide (or state "generated/copied files are exempt"); pre-authorise tool-file splits in T22–T24 (e.g. `tools/schema-object-types.ts`, `tools/schema-attributes.ts`) or relax the cap for tool registration files.

### A2. BLOCKER — `tenantWhere` defined in two incompatible places with different signatures
- **Where:** T03 (`packages/db/src/tenant-where.ts`: `tenantWhere(t: TenantRef)` returning `{ organizationId, teamId }`, spread-shape) vs `auth-and-tenancy.md` §3 ("`tenant_scope.ts` exports `tenantWhere(ctx)`") vs the lint script spec in T01 (regex requires the literal text `tenantWhere(`).
- **Breaks:** two file names (`tenant-where.ts` vs `tenant_scope.ts`), two signatures (TenantRef vs ActorContext). A literal implementer does not know which is normative; the lint regex (`prisma\.(record|recordLink|…)\.findMany(` followed within 5 lines by `tenantWhere(`) is satisfied by either, so the mismatch is invisible until two conventions diverge across services.
- **Fix:** pick one: `packages/db/src/tenant-where.ts` with `tenantWhere(tenant: { organizationId, teamId })`, and edit `auth-and-tenancy.md` §3 to name that file and signature. Update the lint description to match.

### A3. BLOCKER — tenant-where lint regex misses half the tenant-scoped models
- **Where:** T01 `scripts/lint-tenant-where.mjs` regex: `prisma\.(record|recordLink|recordChange|objectType|attribute|relationType|list|view|matchingRule|webhook)\.` — omits `recordUniqueKey`, `recordSearch`, `listEntry`, `policyRule`, `policyBinding`, `approvalRequest`, `idempotencyReplay`, and `queueJob` (nullable tenant but still filtered in claim paths). Also omits `findUnique`/`findFirstOrThrow` on models whose unique key is *not* tenant-qualified (`RecordUniqueKey @@unique([attributeId, normalizedValue])` is **cross-tenant** — see C5 — so a `findUnique` there leaks across tenants).
- **Breaks:** the lint passes while queries on unique keys, list entries, policy tables, and approval tables go unscoped — directly against AGENTS.md rule "scope by entitlement". Since all those models have `@@unique` constraints that do not include tenant, `prisma.<model>.findUnique({ where: { attributeId_normalizedValue } })` compiles and bypasses the lint entirely.
- **Fix:** extend the regex model list and op list, or re-scope all `@@unique`/`@unique` constraints to include `(organizationId, teamId)` so tenant-less lookups don't compile. Do both.

### A4. BLOCKER — "run in the worktree" + fixed port 5656 + mandatory `pnpm dev` acceptance
- **Where:** guide §2 ("work only inside that worktree"), T04/T20 acceptance runs `pnpm dev` on `localhost:5656`, T44/T43 deployment keeps 5656. Two concurrent tasks (or a leftover `tsx watch` from the previous task's acceptance, which `pkill -f "tsx watch"` kills only if the pattern matches) collide on the port. `pkill -f "tsx watch"` also kills *any other* tsx watch on the machine (including another worktree's dev server) — destructive and race-prone; and `(pnpm dev … &); sleep 6` may exit 0 with curl succeeding against a *stale* server from an earlier worktree.
- **Fix:** parameterise the port per worktree (`DEEPCRM_API_PORT=5656+<task#>` in `.env`) or have acceptance bind port 0 and parse the log line. Replace `pkill -f` with PID capture.

### A5. MAJOR — T01 acceptance runs lint/typecheck before any package has a buildable graph
- **Where:** T01 acceptance: `pnpm install && pnpm lint && pnpm typecheck`. `typecheck` = `pnpm prisma:generate && turbo run typecheck`. But `prisma generate` in `@deepcrm/db` has **no `schema.prisma` until T03** → `prisma generate` exits non-zero. Also `@deepcrm/db`'s `src/index.ts` is `export {}` at T01, and every package's `tsconfig.json` includes `test` dirs that don't exist yet (fine) but `turbo run lint` requires each package's `lint` script — OK — while `tsconfig.build.json` with `rootDir: src` + `include: ["src"]` is fine. The killer is `prisma generate` with no schema.
- **Fix:** T01 acceptance should be `pnpm install && pnpm lint && pnpm exec turbo run typecheck --filter=@deepcrm/schemas` (or make `prisma:generate` tolerant: `prisma generate` only if schema exists). Alternatively move a minimal `schema.prisma` into T01.

### A6. MAJOR — T08 acceptance requires `js-yaml`-free validation but `pnpm verify` runs full DB-less tests
- **Where:** T08 acceptance: "…exits 0; `pnpm verify` green locally." `pnpm verify` = `lint && typecheck && test`; `turbo run test` has `cache: false` and `env: ["DATABASE_URL"]`. Without `DATABASE_URL` the DB-gated suites skip silently (per AGENTS.md), so this passes — but the guide says acceptance commands run "with `DATABASE_URL` exported when the block says so". T08's block does not say so, yet earlier tasks (T03, T05, T06) required it. A fresh worktree per task means the executor must know to keep Postgres running and the var exported across *all* tasks; the guide never states this globally. Modest LLM will silently run skipped suites and "pass".
- **Fix:** state in the guide: "Postgres from testing.md runs for the whole session; export `DATABASE_URL` in every acceptance that touches packages with DB tests (list them)."

### A7. MAJOR — guide step 3 "Create means the file must not exist yet" vs tasks that re-create or edit pre-listed files
- **Where:** T20 edits `api/src/app.ts` (fine, "Edit" exists), but T26 says "Replace `scripts/generate-mcp-docs.mjs`" — a file created in T01 as a placeholder; the guide defines only Create/Edit, "Replace" is undefined. T41 says "add to `docs/architecture.md` §6 and `.env.example`" — editing `.env.example` is allowed but the guide's "do not add env vars the docs do not name" collides: `DEEPCRM_EXPORT_DIR` is invented by T41 itself (named only inside the task, not in architecture §6 until the task edits it — acceptable, but the guide should bless task-introduced env vars explicitly).
- **Fix:** add "Replace = Edit where content is wholly rewritten"; add "a task may introduce env vars only if it updates architecture.md §6 + .env.example in the same commit" (T41 already does — make it the rule).
